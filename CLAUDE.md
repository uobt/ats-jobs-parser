# ats-jobs-parser — правила проекта

Парсер вакансий с публичных ATS/job-board API. Правила, нарушение которых
тихо ломает данные:

## Жёсткие правила

1. **Внешние базы не трогать.** Парсер работает на собственной SQLite
   (`data/jobs/jobs.db`). Снимок реестра портала (`jobs/portal_snapshot.py`) —
   только read-only сессия, с проверкой counts исходных таблиц до и после.
2. **Идемпотентность.** Любой скрипт перезапускается на том же батче без
   дублей (натуральные ключи + upsert).
3. **Raw → модель.** Всё, что пришло из API, сначала на диск сырым
   (`data/raw/...jsonl`), расчёты — поверх. Перепарсить историю можно
   без повторных запросов.
4. **Никаких выдумок в данных.** Нет даты — поле пустое, а не «сегодня»;
   нет домена — пусто, а не угадано из названия.
5. **Секреты только в `.env`** (в конфигах — имя переменной окружения).
   Для работы парсера ключи не нужны: все эндпоинты публичные.
6. **Ленты и ATS считаются по-разному.** ATS-выдача — полный каталог
   компании: пропавшая вакансия закрывается. Лента — скользящее окно:
   пропажа значит лишь «уехала за край», по лентам вакансии не закрываются
   никогда (`Store.apply_feed_result`). Перепутать эти пути — получить
   пачку ложных «закрытий» и следом ложных «открылось заново».
7. **Вежливый транспорт.** Троттлинг на хост, ретраи только на временные
   ошибки, уважение `Retry-After` (robots.txt Lever объявляет Crawl-delay: 1 —
   это и есть дефолт). Прокси не поддерживаются намеренно.

## Запуск

```bash
python -m unittest tests.test_jobs        # приёмка ядра: 55 тестов
python jobs/run.py run --limit 200        # обход, запись дельты
python jobs/run.py signals --days 14      # компании с сигналом найма
```

Каталоги `data/` в git не попадают. `config/*.yaml` — примеры: скопируйте
под своими именами и правьте под себя.
